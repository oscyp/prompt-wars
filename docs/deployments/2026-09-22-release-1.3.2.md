## Known limitations

The [visual acceptance report](../audits/2026-09-21-visual-remediation/README.md) remains the source for native coverage: 29 inspected captures, with real routes and component fixtures labelled separately. Non-Latin heading clipping at accessibility text size is still reproducible in the tested iOS Debug runtime. Full VoiceOver, OS Reduced Motion, reviewed-human sharing, payment-recovery and performance acceptance remain incomplete. A successful production build does not close these checks. Android validation remains blocked under the user's existing instruction, and Android distribution is excluded from this release.

The previously undeployed avatar endpoint is now active. A post-deployment check on the signed-in 402×874 iPhone simulator confirmed an available current-rival asset, valid signed URL and the displayed generated avatar. A read-only runtime inspection exported availability booleans only; no credentials, profile IDs or signed URLs were recorded. Database counts confirmed the visible rival's approved owned avatar, stored object and absence of a blocking relationship. [Native smoke evidence](../audits/2026-09-22-deployment/native-avatar-smoke.json) and [the capture](../audits/2026-09-22-deployment/rival-after-deploy.jpg) use the existing Debug app, not the new production binary. Rankings showed its ended-season state and visible battle rows were practice bots, so populated Rankings and frozen human battle avatars remain unverified. The simulator returned to Arena; balance stayed at 129 credits and no account mutation was performed.

The existing Supabase advisor categories reported in the September 14 release remain: the public cosmetic projection view (one ERROR), four mutable-search-path helpers, four authenticated security-definer helpers and disabled leaked-password protection (nine WARN findings). These are recorded in [security-advisories.json](../audits/2026-09-22-deployment/security-advisories.json); they were not silently reclassified or modified during deployment. No table-without-RLS finding was reported.

## Release scope and recovery

No combat/appeal rollout flag or secret was changed. No database reset, historical rejudging, automatic refunds, Git commit/push or public App Store review/release was performed. Existing audio-provider work was preserved as part of the current source rather than edited for this release.

Client rollback is the previous stable **1.3.1 (11)** build (`94c36788-e839-4152-8ab4-8873ab54ab58`). The additive avatar endpoint is compatible with older clients. No schema rollback is needed because this run applied no migrations. For a function rollback, use the previously deployed source and the recorded before/after version manifest; do not infer a rollback source solely from a dirty-tree Git commit.
