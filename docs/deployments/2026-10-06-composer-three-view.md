# Composer: Action → Intention → Review

Status: implementation and bounded native verification complete; Android preview delivered and verified; exact iOS17 submission finished and Apple internal TestFlight testing confirmed. This record covers the approved October 6 client redesign. No backend deployment is part of this change.

## Scope and implementation order

1. Preserve the semantic composer reducer and draft format v3; add optional, validated local `composerStep` metadata and safe restore/back navigation.
2. Split experience v2 into action, intention and exact review views inside the existing battle route. Keep one full editor mounted, nine authored actions available without AI, and explicit Next/Review navigation.
3. Remove inspiration filters and normal draft-status/discard controls. Keep actual storage errors, recovery, per-type AI banks and explicit purchase confirmation.
4. Restore the 600 ms hold on review, retaining exact-text/type confirmation for screen readers and direct guards for closed rounds, deadlines and stale scopes.
5. Run app regressions, TypeScript, scoped lint, independent review and native QA; then freeze the uploaded source archive and produce internal TestFlight and Android preview APK builds. No public store release or backend/judge/ranking change is included.

## Delivery commands

Use the project's supported EAS CLI after verification and source freeze. Build iOS with `build --platform ios --profile production --non-interactive --no-wait --json` and Android with `build --platform android --profile preview --non-interactive --no-wait --json`. Once the exact iOS artifact is finished and verified, use `submit --platform ios --profile production --id BUILD_ID --groups 'Team (Expo)' --groups testers --no-auto-testflight-setup --non-interactive --no-wait`. Record submission completion and fresh `submit:status`; a queued job does not prove tester availability. Keep Android as a preview APK; do not submit it to Google Play.
