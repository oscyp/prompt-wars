## Android IME finding and correction

The original `KeyboardAvoidingView` used iOS padding and no Android behavior. With the software keyboard open, the fixture's fixed Lock in control remained at y2142–2318 while the visible IME occupied y1428–2340; the button and lower editor/caret were covered. Both Expo Go's ExperienceActivity and Android 6's MainActivity report `adjustResize` and `EDGE_TO_EDGE_ENFORCED`, so relying on OS resize was a credible product risk. The production sign-in screen independently used explicit Android height avoidance and resized its content. Before evidence: `android-before-go-keyboard-geometry.png`, matching XML/window dump, and release-window comparison `android-before-final6-keyboard-window.txt`.

The source freeze was lifted only for the composer route and its matching fixture. Android `height` first revealed a 268 px residual gap on hide. RN 0.83's Android KAV hide handler recalculates from a hide-event screenY instead of clearing its bottom; the height branch also adds prior bottom state. The final implementation uses the same existing KAV and editor tree with `Platform.select({ ios: 'padding', android: keyboardVisible ? 'padding' : undefined })` (fixture flag `keyboard`). Android padding is active only while the keyboard is visible; hiding releases it. Padding calculation does not add the retained prior offset. iOS behavior remains padding and web/default remains undefined. No dependency/native configuration changed.

Only `app/(battle)/prompt-entry.tsx` differs among the 503 archived runtime files from iOS 16. `test-support/fixtures/app/prompt-composer.tsx` has the matching change and is excluded from the release archive. The verified Android 7 artifact contains this source; its Hermes disassembly independently confirms the conditional padding. iOS 16 behavior is unchanged.

Three measured cycles from a cold, initially keyboard-closed Go session passed at 1080×2340/440dpi. Every show placed the full CTA at y1230–1406, above IME top 1428. Every hide restored the exact original y2010–2186. The 97-character edited text remained unchanged; no accumulated gap occurred. Android's spelling popup was dismissed with Back when it intercepted the accessibility hierarchy; no spelling correction was accepted. Evidence: `android-go-padding-show1.png` through `show3.png`, corresponding `hide1.png` through `hide3.png`, XML files and `android-keyboard-cycle-proof.json`. The native editor remained mounted; the initial typed 97-character caret was visibly above the keyboard. Automated workspace coverage also verifies mounted-editor behavior through keyboard events.
