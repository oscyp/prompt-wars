# App shell, profile group and entry funnel — UX/UI audit (2026-09-03)

_Companion to `BATTLE_FLOW_UX_AUDIT.md`. Scope: the tab shell (`(tabs)` — Arena, Battles,
Rankings, Profile, the raised Battle button and mode sheet), the profile group (`(profile)` —
wallet, shop, stats, settings, blocked; edit-character was redesigned separately this week),
and the entry funnel (`app/_layout.tsx` gate, sign-in, sign-up, welcome, create-character).
Method: full code survey against `docs/DESIGN_LANGUAGE.md`, the concept doc and mobile-game
conventions, followed by an implementation pass. Backend was not changed._

## Verdict

The shell is honest about what it is: a utility layer around a good battle spine. Its problems
are of one kind, repeated: **a failed request renders as legitimate data**. A wallet whose
balance failed to load shows "0 Credits"; a stats screen whose profile failed to load shows
rating 1500 and an all-zero record; a Battles tab whose fetch failed says "No battles yet. Start
your first battle!"; the Arena blanks every section when one of five parallel calls fails.
Players are told they have nothing when the app could not ask.

Three findings are outright defects rather than roughness:

- **Sign-out leaked push notifications.** Two screens called the Supabase client directly,
  skipping the provider that deactivates the device's push token, so a signed-out device kept
  receiving that account's battle notifications.
- **Abandoned onboarding drafts became real characters.** The creation flow pre-inserts a
  character row for the portrait step; the auth gate keyed on `is_active` alone, so a player who
  quit at step 4 came back to a battle-eligible fighter named after their draft with an ellipsis
  for a battle cry, and no way back into onboarding.
- **Equipping a signature colour in the shop rewrote the character.** The server's equip path
  writes `signature_color`, bumping the appearance version and marking the paid portrait stale,
  while the shop's own copy promised "You choose when to wear it."

Beneath those: the payoff loop is thin (quest claims give no reward feedback, a purchased
cosmetic is indistinguishable from a refresh, account creation ends in an instant screen swap),
currency vocabulary is improvised per screen although `formatCredits` exists for exactly this,
the wallet ledger prints machine keys such as `render_look_refund:timeout`, and the funnel has
no forgot-password path at all.

## Findings and disposition

Severity: **P1** wrong or blocking · **P2** materially hurts play or trust · **P3** craft.

## What was built (shared)

- `utils/battleCopy.ts` gains `battleStatusView`, `battleOutcomeFor`, `opponentNameFor`,
  `formatRemaining` (moved from the versus strip).
- `utils/walletCopy.ts` — `transactionLabel`, `transactionAmountLabel`, tested.
- `utils/prebattleCopy.ts` — the matchmaking and waiting copy, moved out of the route files.
- `utils/battleLists.ts` — `getActiveBattles` / `getBattleHistory` (server-side status filter,
  Bo3 round lock stamps embedded), `describeBattleRow`, `sortBattlesForList` (your turn first),
  `battleRouteFor`, `statusToneColor`. Arena and Battles share it.
- `utils/rankingsView.ts` — medal tier, rank display, ordinal a11y labels, viewer-row pinning.
- `hooks/useTabClearance.ts` — the one place that decides how much a tab list pads above the
  raised Battle button.
- `utils/storePackages.ts` — `findPackageForProduct` (current offering first, then all) and
  `offerPriceStrings` (store price; USD reference only on USD storefronts).
- `utils/walletView.ts` — unlock/earn hints, cosmetic error copy map, balance polling delays,
  subscription renewal/manage/disclosure copy. `utils/settingsCopy.ts` — notification and
  haptics copy, version label.
- `RevenueCatProvider` — `purchase()` returns `purchased | cancelled | failed`, `restorePurchases()`
  returns `restored | nothing | failed`; debug logging gated on `__DEV__`.
- `useCredits` exposes `error`; `CreditChip` has an `unavailable` state and a 44 pt hit target.
- `StreakMeter` exports `loginDots` / `nextWinMilestone`; `SectionCard` title carries the header
  role. `FirstTimeOfferModal` accepts `priceString` / `referencePriceString` (`null` suppresses).
- `utils/authCopy.ts` — `classifyAuthError` / `describeAuthError` (by code, never prose),
  validators, `signUpOutcome`, `parseRecoveryLink`, notices. `utils/onboardingDraft.ts` — step
  model (`canAdvance`, `nextDisabledHint`, `clampStepToDraft`, `finalizeBlocker`), staleness,
  money copy, error describers duck-typed on `status`/`body`, device-local draft persistence.
- `AuthProvider` owns the route gate (`useRouteGate`), password recovery
  (`recoveryPending`, `completeRecovery`) and no longer registers push on sign-in; push registers
  once a finalized character exists.
- Profile (second pass): `utils/profileView.ts` — `ratingView`, `isRatedBattle`, `nextUnlock`, rival
  record/identity, `progressionRows`, `fighterCardCopy`; `utils/profileData.ts` — the six reads
  plus rival assembly, item names memoised per session; `components/profile/` — `FighterHero`,
  `ProgressionStrip`, `RivalRow`, `ProfileSkeleton`. Share captures the hero itself.
- Profile-tab and Settings sign-out through `AuthProvider`.
- Screen changes as listed in the tables above.

## Deferred (needs backend or product decisions)

1. Stop `equip_cosmetic` writing `signature_color` for colour cosmetics (W1); the client no
   longer offers the path, so this is hygiene.
2. Typed confirmation or re-authentication before account deletion (W15).
3. Username picker with server-side uniqueness (F20).
4. Supabase Auth config: add `promptwars://reset-password` to the allowed redirect URLs, and
   confirm the email-confirmation setting matches the sign-up copy (F3/F4). Not verifiable from
   the client.
5. A Retry when the gate's character read fails; today it falls back to onboarding.
6. Lift the three auth screens' `FieldError` and password-reveal row into `components/`.
7. An `onPrimary` token or darker button fill in the dark theme (F21, battle S6).
8. A reference product on the first-time offer (or a localized reference price from the server)
   so non-US storefronts can show a real "usually" price; today the anchor is hidden there rather
   than derived, because a reference price has to be a real one.
9. `daily_quest`, `season_ending` and `friend_challenge` pushes are routed on the client but not
   yet sent by the server; routing keys on `data.type`.
10. On-device pass: SE-class phone, Dynamic Type XXL, VoiceOver through sign-up → creation →
    first battle → wallet purchase. The Arena's `battle_rounds` embed and `NOT IN` status filter
    are unverified against the live project; a PostgREST rejection surfaces as the section's error
    banner, not a blank screen.
